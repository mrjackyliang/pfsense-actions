Short, practical definitions for the API, console, notification, and deployment terms used throughout the pfSense Actions documentation. Tables list the term first, also known as, then the definition.

## Core Concepts

| Term                         | Also known as     | Definition                                                                                                                                                                                                                                                                    |
|------------------------------|-------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **action**                   | —                 | One allowlisted pfSense operation behind its own HTTP route: `GET /api/v1/connectivity`, `GET /api/v1/system`, `POST /api/v1/ping`, or `POST /api/v1/wol`. Each also answers at a root path, such as `POST /wol`, runs a fixed command shape, and requires exactly one scope. |
| **allowlist**                | —                 | The closed set of commands the controller runs on pfSense: `whoami`, `uname -mrs`, `ping -c 5 <address>`, and `wol -i <broadcast> <mac>`. Values come only from validated request fields, and no route accepts a command string.                                              |
| **controller**               | —                 | The pfSense Actions service that checks tokens, validates requests, runs allowlisted commands over SSH, and serves the operations console at `/admin`. Clients talk to it, never directly to the firewall.                                                                    |
| **target firewall**          | —                 | The one pfSense firewall whose IP address, SSH port, username, and credential are stored in the controller database. Each deployment manages exactly one.                                                                                                                     |
| **data-minimizing response** | —                 | A reply that reports the outcome without returning firewall output, such as `{"connected": true}` or an error code and message. Only `GET /api/v1/system` returns firewall details, limited to three validated fields.                                                        |
| **operations console**       | console, `/admin` | The browser interface at `/admin` for the administrator account, personal access tokens, the activity log, the pfSense connection, notifications, and sign-in security. It manages the controller only and can't run commands or change firewall settings.                    |

## Access Tokens

| Term                      | Also known as | Definition                                                                                                                                                                                                                |
|---------------------------|---------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **personal access token** | access token  | A credential for one script or integration, made of `pfa_` and 43 random characters, with one or more scopes and an optional expiry. The controller stores only its token hash, identifier, name, scopes, and timestamps. |
| **scope**                 | —             | A named capability granted to a personal access token: `pfsense:read`, `reachability:read`, or `wol:execute`. Scopes are exact, so no scope grants access to another scope's routes.                                      |
| **token identifier**      | token ID      | The fixed ID of a personal access token, like `tok-3f9a1c2b7d4e5f60`, which pfSense Actions picks when the token is created and never changes.                                                                            |
| **token name**            | —             | The label you give a token, like `Home Assistant`, up to 80 characters and unique regardless of letter case. You can change it at any time, and it appears as the actor in the activity log.                              |
| **token hash**            | —             | The SHA-256 digest of a raw personal access token, the only form of the token the controller stores. A lost token can't be recovered from its hash, only replaced.                                                        |
| **rate limit**            | —             | A cap on requests from one client: an IPv4 address or an IPv6 `/56` network. Action routes allow 3 per 10 seconds, every route under `/api/v1` 120 per minute, and console sign-in 10 failures per 15 minutes.            |

## API Actions

| Term                   | Also known as              | Definition                                                                                                                                                                                                            |
|------------------------|----------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **connectivity check** | `GET /api/v1/connectivity` | The action, also at `GET /`, that signs in to the target firewall over SSH, runs `uname -mrs`, and answers `{"connected": true}` or an error. It requires the `pfsense:read` scope.                                   |
| **system information** | `GET /api/v1/system`       | The action, also at `GET /system`, that returns the firewall's `operatingSystem`, `release`, and `architecture` as reported by `uname -mrs`. Output that doesn't split into exactly those three fields returns `502`. |
| **reachability check** | `POST /api/v1/ping`        | The action, also at `POST /ping`, that asks the target firewall to ping one IP address for up to `count` ping attempts. It requires the `reachability:read` scope.                                                    |
| **ping attempt**       | —                          | One run of `ping -c 5 <address>` on the firewall during a reachability check. The request's `count`, from 1 to 10, sets the maximum number of attempts, so one request can send up to 50 echo requests.               |
| **strict mode**        | `"strict": true`           | A reachability check option that counts a ping attempt as reachable only when it reports `0.0% packet loss`. Without it, any attempt that gets at least one reply counts.                                             |
| **Wake-on-LAN**        | WoL, `POST /api/v1/wol`    | A way to power on a sleeping device with a "magic packet" its network card listens for. The action, also at `POST /wol`, has pfSense send it with the `wol` command and requires the `wol:execute` scope.             |
| **broadcast address**  | —                          | The address that reaches every device on a subnet, such as `192.0.2.255` for `192.0.2.0/24`. Wake-on-LAN packets don't cross subnets, so use the broadcast address of the device's own subnet.                        |
| **MAC address**        | hardware address           | A device's hardware address, written as six colon-separated pairs of hexadecimal digits, such as `00:11:22:33:44:55`. pfSense Actions accepts it in all lowercase or all uppercase.                                   |

## Console Sign-In

| Term                      | Also known as       | Definition                                                                                                                                                                                                                                                                      |
|---------------------------|---------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **administrator account** | —                   | The single local username and password that signs in to the operations console, with the password stored as an Argon2id hash. You create it with the setup code, and personal access tokens and pfSense credentials can't sign in to the console.                               |
| **setup code**            | —                   | A one-time code in three groups of five characters, such as `ABCDE-FGHJK-LMNPQ`, that pfSense Actions prints in its log while no administrator account exists; entering it on the setup screen creates the account. A code lasts 30 minutes, and each restart prints a new one. |
| **bootstrap value**       | `PFSENSE_*`         | A deprecated, optional setting that fills a new controller database with pfSense connection values, applying only while nothing of its kind is saved yet. The console replaces them, so changing one later has no effect.                                                       |
| **browser session**       | —                   | The signed-in state the operations console keeps for 24 hours from sign-in, stored in the controller database. Sessions survive restarts, and changing the password ends every session except the one that made the change.                                                     |
| **CSRF token**            | `X-CSRF-Token`      | A random value issued with each browser session that the console sends in the `X-CSRF-Token` header with every change. A change request without the matching value is rejected with `403`.                                                                                      |
| **TOTP**                  | authenticator code  | A time-based one-time password: the six-digit code an authenticator app shows, which changes every 30 seconds. Once you turn it on, password sign-in also asks for a code, and each code works only once.                                                                       |
| **recovery code**         | —                   | One of ten single-use codes, such as `7KQ2M-XW9PD`, shown once when you turn on the authenticator app. It can stand in for an authenticator code at sign-in, and the controller stores only a hash of each one.                                                                 |
| **passkey**               | WebAuthn credential | A credential kept by your device or password manager that signs in to the console without a username, password, or TOTP code. It's bound to the hostname it was added on, and the controller stores only its public key and usage details.                                      |
| **relying party**         | —                   | The identity a passkey is bound to, taken from the hostname in the browser when you add the passkey. That hostname has to be a domain name served over HTTPS, or `localhost`.                                                                                                   |

## Console Activity and Secrets

| Term                  | Also known as | Definition                                                                                                                                                                                                                                                                                                           |
|-----------------------|---------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **activity log**      | —             | The redacted history of authenticated API actions, console sign-ins, and administrative changes, stored in the controller database. The newest 250 events are kept, and the console shows all of them.                                                                                                               |
| **Confirm it’s you**  | —             | The fresh account check before an export or import, using the password and current authenticator code when enabled, or a passkey. It issues a five-minute grant that works once, only for that operation and browser session.                                                                                        |
| **connection test**   | —             | A live SSH sign-in to pfSense that the console runs with the saved settings or with proposed new ones. It checks that sign-in works and doesn't run any action.                                                                                                                                                      |
| **write-only secret** | —             | A credential kept out of ordinary console pages and API read routes, such as the stored SSH password or private key, or a destination's secret field. Leaving the field blank keeps it, though switching the SSH authentication method needs a new one, and a freshly confirmed export can include it in plain text. |

## Notifications

| Term                         | Also known as | Definition                                                                                                                                                                                                                                                                                                        |
|------------------------------|---------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **notification destination** | destination   | One place alerts go, such as an ntfy topic, a Telegram chat, an email address, or a webhook, set up on the console's **Notifications** page. Each has a name, a service, the events it hears about, and the service's fields.                                                                                     |
| **notification event**       | event         | Something pfSense Actions can send an alert about: **Saved secrets were removed**, **Sign-in locked**, **pfSense can't be reached**, **pfSense reachable again**, **Action failed**, or **Wake-on-LAN sent**. Each destination chooses its own events, and the first four are checked when you add one.           |
| **scheduled check**          | —             | The SSH sign-in and `uname -mrs` that pfSense Actions runs every 5 minutes while a destination hears about **pfSense can't be reached** or **pfSense reachable again**. Two failed checks in a row send the first, and the next check that succeeds sends the second.                                             |
| **secret field**             | —             | A destination field, such as a token, key, password, or webhook URL, that's encrypted with the encryption key and kept out of ordinary pages and read routes. Leaving it blank keeps the saved value, a freshly confirmed export can include it in plain text, and a start without the encryption key removes it. |
| **notification payload**     | payload       | The JSON body that Webhook and Reverse Proxy for ntfy destinations receive, with `version`, `app`, `event`, `title`, `message`, `priority`, `tags`, `occurredAt`, and `details`. Its `app` is always `pfsense-actions`.                                                                                           |

## Storage and Backups

| Term                    | Also known as                      | Definition                                                                                                                                                                                                                                                                                                                       |
|-------------------------|------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **controller database** | `database/pfsense-actions.sqlite3` | The SQLite file under the state root holding the administrator account, browser sessions, token hashes, the encrypted pfSense connection, TOTP, recovery code, and passkey records, notification destinations, and the activity log. The controller creates it readable only by its own user.                                    |
| **data volume**         | `pfsense_actions_data`             | The Docker named volume mounted at `/config` that holds the controller database under `database/` and the generated encryption key under `keys/`. Removing it deletes every token, setting, and activity record.                                                                                                                 |
| **encryption key**      | `keys/installation.key`            | A key stored as 64 lowercase hexadecimal characters plus a newline, generated on the first start in a `0700` folder with file mode `0600`. It encrypts the pfSense credential, the TOTP secret, and destinations' secret fields. If it goes missing, pfSense Actions makes a new key and removes the secrets the old one sealed. |
| **export file**         | —                                  | A portable JSON backup of the sections selected under **Connection** > **Backup** > **Export…**, which moves without the source encryption key. It contains selected passwords and keys in plain text, and stores access-token hashes instead of raw token values.                                                               |

## pfSense SSH Access

| Term                      | Also known as                         | Definition                                                                                                                                                                                  |
|---------------------------|---------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **shell account access**  | `User - System: Shell account access` | The pfSense user privilege that lets an account sign in over SSH. pfSense Actions doesn't check privileges, so it's worth confirming the account can run the allowlisted commands.          |
| **authorized SSH key**    | —                                     | The public half of an SSH key pair, added to the pfSense user so the controller can sign in with the matching private key. Passphrase-protected private keys aren't supported.              |
| **host key verification** | —                                     | Checking that an SSH server's host key matches a known value before trusting the connection. pfSense Actions doesn't verify host keys yet, so it accepts whichever key the server presents. |

## Deployment and Container

| Term                 | Also known as | Definition                                                                                                                                                                                                                                             |
|----------------------|---------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **reverse proxy**    | —             | A web server, such as Caddy, that serves HTTPS to clients and forwards requests to the controller's local listener. The controller reads the forwarded client address and protocol only from proxies on private or loopback addresses.                 |
| **loopback binding** | `127.0.0.1`   | Exposing a service only on the host loopback address, so only the host and software on it can connect. pfSense Actions uses host networking; a same-host proxy connects through loopback while the host firewall blocks other clients from port 22603. |
| **s6-overlay**       | —             | The process supervisor that runs as the container's first process. It checks `PUID`, `PGID`, and `TZ`, prepares state, then starts the controller as that user. A nonzero exit from the essential controller service stops the container.              |
| **health check**     | `GET /health` | The Docker check that runs every 30 seconds and marks the container unhealthy after 3 failures in a row. It confirms every required s6 service is up and the local endpoint answers `200`, and it never contacts pfSense.                              |
