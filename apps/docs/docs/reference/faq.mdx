Find answers to common questions about what pfSense Actions supports, how it handles security, and where to get help.

## Product

### Can pfSense Actions change firewall rules or run any command?

No. It runs only its <Terminology title="The only commands it will ever run on pfSense" to="/docs/reference/terminology#core-concepts">allowlisted</Terminology> commands, and the <Terminology title="The /admin web page for tokens and settings" to="/docs/reference/terminology#core-concepts">operations console</Terminology> manages tokens, activity, the connection, notifications, and the <Terminology title="The one login for the console; tokens can't sign in" to="/docs/reference/terminology#console-sign-in">administrator account</Terminology>, not firewall settings.

### Why use pfSense Actions instead of an API package on pfSense?

pfSense Actions needs only SSH and commands that ship with pfSense, so nothing extra gets installed on the firewall. It also limits each client to four <Terminology title="One fixed pfSense task you can call, like ping or wake" to="/docs/reference/terminology#core-concepts">actions</Terminology> and the <Terminology title="What a token may do; each action needs exactly one" to="/docs/reference/terminology#access-tokens">scopes</Terminology> you grant.

### Can one deployment manage several firewalls?

No. Each deployment stores the connection for one <Terminology title="The one pfSense box this install controls" to="/docs/reference/terminology#core-concepts">target firewall</Terminology>.

### Can pfSense Actions tell me when the firewall goes down?

Yes. Add a <Terminology title="Where an alert goes: ntfy, Telegram, email, webhook" to="/docs/reference/terminology#notifications">notification destination</Terminology> that chose **pfSense can't be reached**, and a <Terminology title="A sign-in every 5 minutes to notice pfSense going down" to="/docs/reference/terminology#notifications">scheduled check</Terminology> signs in to pfSense every 5 minutes and sends the alert after two failures in a row, as described in [Notifications](/docs/console/notifications/#the-scheduled-check).

## pfSense

### Which pfSense versions work?

pfSense Actions doesn't check the version, and there's no tested version list yet. It needs SSH and the `whoami`, `uname`, `ping`, and `wol` commands, and bug reports are considered for the releases Netgate lists as supported.

### Can I use a hostname for the firewall?

No. The connection takes an IPv4 or IPv6 address, both in `PFSENSE_SSH_IP` and on the console's [pfSense Connection](/docs/console/pfsense-connection/) page.

### Does it support IPv6?

The request bodies and the connection accept IPv6 addresses, but IPv6 targets aren't covered by tests. <Terminology title="Turns on a sleeping device with a magic packet" to="/docs/reference/terminology#api-actions">Wake-on-LAN</Terminology> needs an IPv4 <Terminology title="The subnet-wide address the wake packet is sent to" to="/docs/reference/terminology#api-actions">broadcast address</Terminology>, because IPv6 doesn't have one.

### Does it check the firewall's SSH host key?

Not yet. It accepts whichever host key the server presents, so it's recommended to keep the path to the firewall on a trusted network, as described in the [Security Model](/docs/operations/security-model/#ssh-credential-and-host-keys).

## Security

### Can I expose pfSense Actions directly to the internet?

It's not recommended, because the listener serves plain HTTP and each token stays valid until it expires or is revoked. A <Terminology title="The HTTPS front door, like Caddy, ahead of the controller" to="/docs/reference/terminology#deployment-and-container">reverse proxy</Terminology> with HTTPS, as in [HTTPS Reverse Proxy](/docs/getting-started/https-reverse-proxy/), keeps tokens encrypted in transit.

### What should I do if a token leaks?

Revoke it on the console's **Access tokens** page, which rejects it from the next request on. Then create a replacement for the client, as described in [Access Tokens](/docs/console/access-tokens/#rotate-a-token).

### Where are secrets stored?

The <Terminology title="The one SQLite file that holds everything" to="/docs/reference/terminology#storage-and-backups">controller database</Terminology> holds each <Terminology title="All that's stored of a token; lose it and you replace it" to="/docs/reference/terminology#access-tokens">token hash</Terminology>, the encrypted pfSense credential, the encrypted <Terminology title="The six-digit code from your authenticator app" to="/docs/reference/terminology#console-sign-in">TOTP</Terminology> secret, and the encrypted <Terminology title="A destination's token or password, saved but never shown" to="/docs/reference/terminology#notifications">secret fields</Terminology> of each <Terminology title="Where an alert goes: ntfy, Telegram, email, webhook" to="/docs/reference/terminology#notifications">notification destination</Terminology>, while the <Terminology title="Locks saved secrets; lose it and they're wiped" to="/docs/reference/terminology#storage-and-backups">encryption key</Terminology> stays in its own file. [Data at Rest](/docs/operations/security-model/#data-at-rest) has the details.

### What happens if the encryption key is lost?

pfSense Actions makes a new key at the next start and removes only the saved pfSense password or private key, the authenticator app, and the <Terminology title="A destination's token or password, saved but never shown" to="/docs/reference/terminology#notifications">secret fields</Terminology> of <Terminology title="Where an alert goes: ntfy, Telegram, email, webhook" to="/docs/reference/terminology#notifications">notification destinations</Terminology>, which the console then asks you to enter again. Tokens, <Terminology title="Sign in with your device, no password or code needed" to="/docs/reference/terminology#console-sign-in">passkeys</Terminology>, settings, and the <Terminology title="Who did what and when, for the newest 250 events" to="/docs/reference/terminology#console-activity-and-secrets">activity log</Terminology> stay, as described in [Backup and Recovery](/docs/operations/backup-and-recovery/#lost-encryption-key).

### Can I move the connection and notifications to another installation?

Yes. Use **Export…** under **Connection** > **Backup**, select the sections to include, and import the resulting <Terminology title="A JSON backup that can hold secrets in plain text" to="/docs/reference/terminology#storage-and-backups">export file</Terminology> on the destination. The file does not need the source <Terminology title="Locks saved secrets; lose it and they're wiped" to="/docs/reference/terminology#storage-and-backups">encryption key</Terminology>, because the destination seals imported secrets with its own key.

The file contains a selected pfSense password or private key and notification secrets in plain text, so protect it like those credentials. [Export and Import](/docs/console/pfsense-connection/#export-and-import) lists what is replaced, added, skipped, and kept local.

### Does an export reveal my access tokens?

No. pfSense Actions stores only each <Terminology title="All that's stored of a token; lose it and you replace it" to="/docs/reference/terminology#access-tokens">token hash</Terminology>, so the file cannot reveal a raw token value.

Importing a hash keeps that token value working on the destination. A token with a matching ID, case-insensitive name, or hash is skipped instead of duplicated.

## Support

### Where do I report a bug or ask for a feature?

Open an issue in the [GitHub repository](https://github.com/mrjackyliang/pfsense-actions/issues) with the bug report or feature request form.

### Can I get one-on-one help?

Support requests are open to [GitHub Sponsors](https://github.com/sponsors/mrjackyliang) and to people who have contributed heavily to the project.
