Review what happened in pfSense Actions, from API requests to sign-ins and settings changes, with sensitive details left out.

## Why Use the Activity Log?

1. Shows which token ran which <Terminology title="One fixed pfSense task you can call, like ping or wake" to="/docs/reference/terminology#core-concepts">action</Terminology>, and whether it worked.
2. Records failed sign-ins along with successful ones.
3. Leaves out IP addresses, <Terminology title="The device's hardware ID that the wake packet targets" to="/docs/reference/terminology#api-actions">MAC addresses</Terminology>, request bodies, and credentials, so reviewing it doesn't expose them.

## Read an Event

On a phone, **Activity** is the second tab in the four-tab bottom bar.

The **Activity** page lists events with the newest first, and **Overview** shows the newest 8 under **Recent activity**. Each event shows:

- **Status** — A green dot for `succeeded` or a red dot for `failed`.
- **Summary** — What happened, such as `Completed Wake-on-LAN request`.
- **Details** — The event name, the actor, and the category.
- **Time** — How long ago it happened, with the full date for older events.

## Filter Events

The chips above the list are page filters at every screen width, and they narrow the events without changing pages.

| Chip              | Shows                                                                                                                                                                                                                                                |
|-------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **All**           | Every event.                                                                                                                                                                                                                                         |
| **Access**        | API requests, sign-ins, and sign-in security changes.                                                                                                                                                                                                |
| **Tokens**        | Tokens being created, edited, and revoked.                                                                                                                                                                                                           |
| **Configuration** | Connection tests and changes, backup imports, debug logging changes, and changes to <Terminology title="Where an alert goes: ntfy, Telegram, email, webhook" to="/docs/reference/terminology#notifications">notification destinations</Terminology>. |
| **Service**       | Events from pfSense Actions itself, such as creating the database.                                                                                                                                                                                   |
| **Failed**        | Every event that failed, from any category.                                                                                                                                                                                                          |

## Actors

- **<Terminology title="The label you pick so you know which app uses a token" to="/docs/reference/terminology#access-tokens">Token name</Terminology>** — For API requests, the name the token had when it made the request.
- **Administrator username** — For sign-ins and changes made in the console.
- **`anonymous`** — For failed sign-in and setup attempts.
- **`system`** — For events from pfSense Actions itself.

## What Gets Recorded

| Event                     | Category      | When it's recorded                                                                                                                                                                                                                                                                                                          |
|---------------------------|---------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `connectivity-check`      | Access        | A connectivity request ran.                                                                                                                                                                                                                                                                                                 |
| `system-information`      | Access        | A system information request ran.                                                                                                                                                                                                                                                                                           |
| `reachability-check`      | Access        | A ping request ran, including one rejected for an invalid body.                                                                                                                                                                                                                                                             |
| `wake-on-lan`             | Access        | A Wake-on-LAN request ran, including one rejected for an invalid body.                                                                                                                                                                                                                                                      |
| `installation-claimed`    | Access        | Someone created the administrator account with the <Terminology title="The one-time code from the log that creates your login" to="/docs/reference/terminology#console-sign-in">setup code</Terminology>.                                                                                                                   |
| `installation-claim`      | Access        | Someone entered a wrong or expired <Terminology title="The one-time code from the log that creates your login" to="/docs/reference/terminology#console-sign-in">setup code</Terminology>.                                                                                                                                   |
| `sign-in`                 | Access        | Someone signed in, or a sign-in attempt failed.                                                                                                                                                                                                                                                                             |
| `sign-out`                | Access        | The administrator signed out.                                                                                                                                                                                                                                                                                               |
| `password-changed`        | Access        | The administrator's password changed.                                                                                                                                                                                                                                                                                       |
| `username-changed`        | Access        | The administrator's username changed.                                                                                                                                                                                                                                                                                       |
| `totp-enabled`            | Access        | An authenticator app was turned on.                                                                                                                                                                                                                                                                                         |
| `totp-disabled`           | Access        | The authenticator app was turned off.                                                                                                                                                                                                                                                                                       |
| `recovery-codes-replaced` | Access        | New <Terminology title="A one-use backup code for when your phone is gone" to="/docs/reference/terminology#console-sign-in">recovery codes</Terminology> replaced the old ones.                                                                                                                                             |
| `passkey-created`         | Access        | A <Terminology title="Sign in with your device, no password or code needed" to="/docs/reference/terminology#console-sign-in">passkey</Terminology> was added.                                                                                                                                                               |
| `passkey-removed`         | Access        | A <Terminology title="Sign in with your device, no password or code needed" to="/docs/reference/terminology#console-sign-in">passkey</Terminology> was removed.                                                                                                                                                             |
| `token-created`           | Tokens        | A token was created.                                                                                                                                                                                                                                                                                                        |
| `token-updated`           | Tokens        | A token's name, <Terminology title="What a token may do; each action needs exactly one" to="/docs/reference/terminology#access-tokens">scopes</Terminology>, or expiration changed.                                                                                                                                         |
| `token-revoked`           | Tokens        | A token was revoked.                                                                                                                                                                                                                                                                                                        |
| `backup-imported`         | Configuration | A confirmed import applied the backup sections it selected.                                                                                                                                                                                                                                                                 |
| `debug-logging-updated`   | Configuration | **Debug logging** was turned on or off.                                                                                                                                                                                                                                                                                     |
| `connection-tested`       | Configuration | Someone tested the saved connection.                                                                                                                                                                                                                                                                                        |
| `connection-update`       | Configuration | Proposed connection settings failed their test and weren't saved.                                                                                                                                                                                                                                                           |
| `connection-updated`      | Configuration | New connection settings passed their test and were saved, or the deprecated `PFSENSE_*` variables filled them in at startup.                                                                                                                                                                                                |
| `notification-created`    | Configuration | A <Terminology title="Where an alert goes: ntfy, Telegram, email, webhook" to="/docs/reference/terminology#notifications">notification destination</Terminology> was added.                                                                                                                                                 |
| `notification-updated`    | Configuration | A <Terminology title="Where an alert goes: ntfy, Telegram, email, webhook" to="/docs/reference/terminology#notifications">notification destination</Terminology>'s name, <Terminology title="What happened that's worth an alert" to="/docs/reference/terminology#notifications">events</Terminology>, or settings changed. |
| `notification-removed`    | Configuration | A <Terminology title="Where an alert goes: ntfy, Telegram, email, webhook" to="/docs/reference/terminology#notifications">notification destination</Terminology> was removed.                                                                                                                                               |
| `state-initialized`       | Service       | pfSense Actions created a new <Terminology title="The one SQLite file that holds everything" to="/docs/reference/terminology#storage-and-backups">controller database</Terminology>.                                                                                                                                        |
| `encryption-key-replaced` | Service       | A missing <Terminology title="Locks saved secrets; lose it and they're wiped" to="/docs/reference/terminology#storage-and-backups">encryption key</Terminology> was replaced, and its secrets were removed.                                                                                                                 |

API requests rejected for a missing, malformed, unknown, or expired token, a missing <Terminology title="What a token may do; each action needs exactly one" to="/docs/reference/terminology#access-tokens">scope</Terminology>, or a <Terminology title="How many requests one IP gets before it's turned away" to="/docs/reference/terminology#access-tokens">rate limit</Terminology> aren't recorded, and neither are requests answered `503` because no connection is saved.

Alerts, **Send test**, and the <Terminology title="A sign-in every 5 minutes to notice pfSense going down" to="/docs/reference/terminology#notifications">scheduled check</Terminology> aren't recorded either. Each <Terminology title="Where an alert goes: ntfy, Telegram, email, webhook" to="/docs/reference/terminology#notifications">destination</Terminology>'s row on [Notifications](/docs/console/notifications/) shows its last send instead.

## What's Never Recorded

- Tokens, passwords, private keys, setup and recovery codes, and authenticator secrets.
- Notification settings and <Terminology title="A destination's token or password, saved but never shown" to="/docs/reference/terminology#notifications">secret fields</Terminology>, since the events name only the <Terminology title="Where an alert goes: ntfy, Telegram, email, webhook" to="/docs/reference/terminology#notifications">destination</Terminology>.
- Request bodies, including any IP or <Terminology title="The device's hardware ID that the wake packet targets" to="/docs/reference/terminology#api-actions">MAC addresses</Terminology> in them.
- SSH output and error details.

## Retention

- pfSense Actions keeps the newest 250 events and deletes older ones as new events arrive, and the **Activity** page shows all of them.
- The log lives in the <Terminology title="The one SQLite file that holds everything" to="/docs/reference/terminology#storage-and-backups">controller database</Terminology>, so it survives restarts but not the removal of the <Terminology title="The Docker volume that keeps your data across updates" to="/docs/reference/terminology#storage-and-backups">data volume</Terminology>.

:::info
The <Terminology title="Who did what and when, for the newest 250 events" to="/docs/reference/terminology#console-activity-and-secrets">activity log</Terminology> is a local, bounded history, not a tamper-resistant audit trail or a replacement for central logging.
:::
