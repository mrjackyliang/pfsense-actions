Create a <Terminology title="a scoped credential issued to one API client" to="/docs/reference/terminology#personal-access-token">personal access token</Terminology> for each script or integration, and edit or revoke it in the console whenever you need to.

## Why Use Separate Tokens?

1. Gives each client only the <Terminology title="a named capability granted to a token" to="/docs/reference/terminology#scope">scopes</Terminology> it needs.
2. Lets you revoke one client without affecting the others.
3. Shows which client did what, because the <Terminology title="a bounded, redacted history of actions and changes" to="/docs/reference/terminology#activity-log">activity log</Terminology> records the <Terminology title="the label you give a token, shown in the activity log" to="/docs/reference/terminology#token-name">token name</Terminology> behind each request.
4. Ends temporary access on its own when you set an expiration.

## Create a Token

1. Open **Access tokens** and select **Create token**.
2. Enter a **Name** you'll recognize, like the app that uses it, up to 80 characters. Each token needs its own <Terminology title="the label you give a token, shown in the activity log" to="/docs/reference/terminology#token-name">name</Terminology>, and names that differ only in letter case count as the same.
3. Under **Scopes**, choose what the client can do. Each one lists the paths it opens.
   - **`pfsense:read`** — <Terminology title="the route that tests pfSense access" to="/docs/reference/terminology#connectivity-check">Connectivity checks</Terminology> and <Terminology title="the OS, release, and architecture from uname" to="/docs/reference/terminology#system-information">system information</Terminology>.
   - **`reachability:read`** — <Terminology title="asking pfSense whether it can ping an address" to="/docs/reference/terminology#reachability-check">Reachability checks</Terminology> from the firewall.
   - **`wol:execute`** — Sending <Terminology title="waking a sleeping device with a network packet" to="/docs/reference/terminology#wake-on-lan">Wake-on-LAN</Terminology> packets.
4. Under **Expires**, choose **Never**, **In 30 days**, **In 90 days**, or **In 1 year**.
5. Select **Create token**.

## Store the Token Once

The new token appears once, at the top of **Access tokens**, under **Token for** and its name.

1. Select the copy button next to the token, and save the token in the client's secret store.
2. Select **Done**.

pfSense Actions keeps only a <Terminology title="the SHA-256 digest stored instead of the token" to="/docs/reference/terminology#token-hash">token hash</Terminology>, so a lost token can't be shown again. Create a new token instead and revoke the old one.

## Edit a Token

- **Edit** changes a token's name, <Terminology title="a named capability granted to a token" to="/docs/reference/terminology#scope">scopes</Terminology>, and expiration, and the token's value stays the same. Changes apply to the client's next request.
- Under **Expires**, the current expiration stays selected as **Keep** and its date, and **Never** removes it.
- Events already in the <Terminology title="a bounded, redacted history of actions and changes" to="/docs/reference/terminology#activity-log">activity log</Terminology> keep the name the token had when they happened.

## Revoke a Token

Select **Revoke**, then **Revoke** again to confirm. The token is deleted, clients using it are rejected on their next request, and its name becomes free to use again.

## Rotate a Token

1. Create a replacement with a new name and the same <Terminology title="a named capability granted to a token" to="/docs/reference/terminology#scope">scopes</Terminology>.
2. Update the client and check that one request works.
3. Revoke the old token.

## Expired Tokens

An expired token stays in the list, and requests that use it are rejected. Edit it to set a new expiration, or revoke it.

## Calling the API

The **Calling the API** section shows the address clients call, the `Authorization` header they send, and each path with the <Terminology title="a named capability granted to a token" to="/docs/reference/terminology#scope">scope</Terminology> it needs. Select the copy button next to **Base URL** to copy the address the console is open at.
