Create a <Terminology title="The pfa_ key a script sends to call the API" to="/docs/reference/terminology#access-tokens">personal access token</Terminology> for each script or integration, and edit or revoke it in the console whenever you need to.

## Why Use Separate Tokens?

1. Gives each client only the <Terminology title="What a token may do; each action needs exactly one" to="/docs/reference/terminology#access-tokens">scopes</Terminology> it needs.
2. Lets you revoke one client without affecting the others.
3. Shows which client did what, because the <Terminology title="Who did what and when, for the newest 250 events" to="/docs/reference/terminology#console-activity-and-secrets">activity log</Terminology> records the <Terminology title="The label you pick so you know which app uses a token" to="/docs/reference/terminology#access-tokens">token name</Terminology> behind each request.
4. Ends temporary access on its own when you set an expiration.

## Create a Token

1. Open **Access tokens** and select **Create token**.
2. Enter a **Name** you'll recognize, like the app that uses it, up to 80 characters. Each token needs its own <Terminology title="The label you pick so you know which app uses a token" to="/docs/reference/terminology#access-tokens">name</Terminology>, and names that differ only in letter case count as the same.
3. Under **Scopes**, choose what the client can do. Each one lists the paths it opens.
   - **`pfsense:read`** — <Terminology title="Can pfSense Actions sign in to pfSense? Yes or no" to="/docs/reference/terminology#api-actions">Connectivity checks</Terminology> and <Terminology title="pfSense's OS, release, and CPU type, nothing more" to="/docs/reference/terminology#api-actions">system information</Terminology>.
   - **`reachability:read`** — <Terminology title="Ask pfSense to ping a device and say if it answered" to="/docs/reference/terminology#api-actions">Reachability checks</Terminology> from the firewall.
   - **`wol:execute`** — Sending <Terminology title="Turns on a sleeping device with a magic packet" to="/docs/reference/terminology#api-actions">Wake-on-LAN</Terminology> packets.
4. Under **Expires**, choose **Never**, **In 30 days**, **In 90 days**, or **In 1 year**.
5. Select **Create token**.

## Store the Token Once

The dialog then shows the new token once, under **Token for** and its name, with a copy button. Copy it before you select **Done**.

1. Select the copy button next to the token, and save the token in the client's secret store.
2. Select **Done**.

pfSense Actions keeps only a <Terminology title="All that's stored of a token; lose it and you replace it" to="/docs/reference/terminology#access-tokens">token hash</Terminology>, so a lost token can't be shown again. Create a new token instead and revoke the old one.

## Edit a Token

- **Edit** changes a token's name, <Terminology title="What a token may do; each action needs exactly one" to="/docs/reference/terminology#access-tokens">scopes</Terminology>, and expiration, and the token's value stays the same. Changes apply to the client's next request.
- Under **Expires**, the current expiration stays selected as **Keep** and its date, and **Never** removes it.
- Events already in the <Terminology title="Who did what and when, for the newest 250 events" to="/docs/reference/terminology#console-activity-and-secrets">activity log</Terminology> keep the name the token had when they happened.

## Revoke a Token

Select **Revoke**, then **Revoke** again to confirm. The token is deleted, clients using it are rejected on their next request, and its name becomes free to use again.

## Rotate a Token

1. Create a replacement with a new name and the same <Terminology title="What a token may do; each action needs exactly one" to="/docs/reference/terminology#access-tokens">scopes</Terminology>.
2. Update the client and check that one request works.
3. Revoke the old token.

## Expired Tokens

An expired token stays in the list, and requests that use it are rejected. Edit it to set a new expiration, or revoke it.

## Calling the API

The **Calling the API** section shows the address clients call, the `Authorization` header they send, and each path with the <Terminology title="What a token may do; each action needs exactly one" to="/docs/reference/terminology#access-tokens">scope</Terminology> it needs. Select the copy button beside the address under **Base URL** to copy the address the console is open at.
