Open the <Terminology title="The /admin web page for tokens and settings" to="/docs/reference/terminology#core-concepts">operations console</Terminology> in a browser, create the <Terminology title="The one login for the console; tokens can't sign in" to="/docs/reference/terminology#console-sign-in">administrator account</Terminology> on the first visit, and then sign in with a password, an authenticator code, or a <Terminology title="Sign in with your device, no password or code needed" to="/docs/reference/terminology#console-sign-in">passkey</Terminology>.

## Open the Console

Go to the root address on the same origin as the API, such as `https://actions.example.net/`; `/admin` opens the console too. After you sign in, wide screens show five pages in the sidebar, and the account menu at its bottom holds **Appearance**, **Sign-in and security**, and **Sign out**.

| Page                     | What it's for                                                                                                                                                                                                                                    |
|--------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Overview**             | The version and uptime, the pfSense connection with a <Terminology title="A trial SSH sign-in to pfSense that runs nothing" to="/docs/reference/terminology#console-activity-and-secrets">connection test</Terminology>, and recent activity.    |
| **Activity**             | The <Terminology title="Who did what and when, for the newest 250 events" to="/docs/reference/terminology#console-activity-and-secrets">activity log</Terminology>.                                                                              |
| **Access tokens**        | Creating, editing, and revoking each <Terminology title="The pfa_ key a script sends to call the API" to="/docs/reference/terminology#access-tokens">personal access token</Terminology>, and the address and paths that clients call.           |
| **Connection**           | Testing and changing the SSH connection to the firewall.                                                                                                                                                                                         |
| **Notifications**        | Sending alerts to ntfy, Telegram, email, and other services when pfSense stops answering, sign-in is locked, or an action fails, as described in [Notifications](/docs/console/notifications/).                                                  |
| **Sign-in and security** | Your password, username, authenticator app, recovery codes, and <Terminology title="Sign in with your device, no password or code needed" to="/docs/reference/terminology#console-sign-in">passkeys</Terminology>, opened from the account menu. |

Each console page has its own address, while `/` also opens **Overview**.

| Page                     | Address          |
|--------------------------|------------------|
| **Overview**             | `/overview`      |
| **Activity**             | `/activity`      |
| **Access tokens**        | `/access-tokens` |
| **Connection**           | `/connection`    |
| **Notifications**        | `/notifications` |
| **Sign-in and security** | `/account`       |

Browser **Back** and **Forward**, refresh, and bookmarks keep the same page open. If you open one of these addresses while signed out, the console opens it after **Sign in**; an unknown address opens **Overview**, the first page.

On a phone, the bottom bar has **Overview**, **Activity**, **Tokens**, and **More**. **More** opens a sheet with **Connection** and **Notifications**. The account menu opens from your initial at the top and keeps the same three account actions.

## Create the Administrator Account

On a new installation, the console opens on **Set up your account** instead of the sign-in screen.

1. Enter the **One-time code**, which is the <Terminology title="The one-time code from the log that creates your login" to="/docs/reference/terminology#console-sign-in">setup code</Terminology> from the container log. Letter case, spaces, and dashes don't matter.
2. Choose a **Username** and a **Password** of 12 to 1,024 characters, and repeat the password in **Confirm password**. The bar under the field rates it from **Weak** to **Strong**, and any password in that range is accepted.
3. Select **Create account**.

<Frame caption="Creating the administrator account" style={{ maxWidth: 450, marginInline: 'auto' }}>
  <ThemedImage sources={{ light: signInTwoLight, dark: signInTwoDark }} alt="Set up your account screen with a one-time code, the username admin, a password that the bar under it rates Strong, the repeated password, and Create account" width={448} height={735} style={{ maxWidth: '100%', height: 'auto' }} />
</Frame>

- A username is 3 to 64 letters, digits, `.`, `_`, or `-`, starting with a letter or digit.
- A code lasts 30 minutes, and restarting pfSense Actions prints a new one.
- The setup screen appears only while no account exists, so it doesn't come back once you've created one.

## Sign In with a Password

1. Enter the **Username** and **Password** of the <Terminology title="The one login for the console; tokens can't sign in" to="/docs/reference/terminology#console-sign-in">administrator account</Terminology>. The username isn't case-sensitive.
2. Select **Sign in**.

A <Terminology title="The pfa_ key a script sends to call the API" to="/docs/reference/terminology#access-tokens">personal access token</Terminology> or your pfSense login doesn't work here.

## Enter an Authenticator or Recovery Code

If you've turned on an authenticator app, the console asks for a code after the password.

1. Enter the six-digit code the app shows, or one of your <Terminology title="A one-use backup code for when your phone is gone" to="/docs/reference/terminology#console-sign-in">recovery codes</Terminology>.
2. Select **Verify**, or select **Start over** to return to the password step.

<Frame caption="The code step" style={{ maxWidth: 450, marginInline: 'auto' }}>
  <ThemedImage sources={{ light: signInThreeLight, dark: signInThreeDark }} alt="Enter your code screen with a six-digit code in the Code field, the Verify button, and Start over below it" width={448} height={503} style={{ maxWidth: '100%', height: 'auto' }} />

- You have 5 minutes after the password step, and 5 wrong codes end the attempt.
- Each authenticator code and each recovery code works only once. A recovery code works with or without its dash, in any letter case.

## Sign In with a Passkey

1. Select **Sign in with a passkey**.
2. Confirm with your device or password manager when the browser asks.

- A <Terminology title="Sign in with your device, no password or code needed" to="/docs/reference/terminology#console-sign-in">passkey</Terminology> replaces the username, the password, and the authenticator code.
- A <Terminology title="Sign in with your device, no password or code needed" to="/docs/reference/terminology#console-sign-in">passkey</Terminology> works only at the hostname it was added on, as described in [HTTPS Reverse Proxy](/docs/getting-started/https-reverse-proxy/#passkeys-and-the-address).

## Sessions

- A <Terminology title="Keeps you signed in to the console for 24 hours" to="/docs/reference/terminology#console-sign-in">browser session</Terminology> lasts 24 hours from sign-in, and then the console returns to the sign-in screen.
- Sessions are stored in the <Terminology title="The one SQLite file that holds everything" to="/docs/reference/terminology#storage-and-backups">controller database</Terminology>, so restarting or updating pfSense Actions doesn't sign you out.
- Changing the password signs out every other session, and **Sign out** in the account menu ends your own session right away.

## Failed Sign-Ins

- Each failed sign-in appears in the <Terminology title="Who did what and when, for the newest 250 events" to="/docs/reference/terminology#console-activity-and-secrets">activity log</Terminology> with the actor `anonymous`.
- Wrong passwords, wrong codes, rejected <Terminology title="Sign in with your device, no password or code needed" to="/docs/reference/terminology#console-sign-in">passkeys</Terminology>, and wrong passwords entered on **Sign-in and security** from one address share a limit of 10 failures in 15 minutes. After that, sign-in from that address waits until the window passes, and a successful sign-in clears the count.
- The tenth failure also sends **Sign-in locked** to the <Terminology title="Where an alert goes: ntfy, Telegram, email, webhook" to="/docs/reference/terminology#notifications">notification destinations</Terminology> that chose it, as described in [Notifications](/docs/console/notifications/#events).
- The setup screen has its own limit of 10 wrong codes in 15 minutes from one address, and those don't send **Sign-in locked**.

## Appearance

Choose **System**, **Light**, or **Dark** under **Appearance** in the account menu. **System** follows your device's setting, and the choice is saved in this browser only.
