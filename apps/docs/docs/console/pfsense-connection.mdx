Set up and change how pfSense Actions signs in to your firewall, with every change tested before it's saved.

## Why Test Before Saving?

1. Keeps the working connection in place when new settings can't sign in.
2. Treats the password or key as a <Terminology title="You can replace it, but the console never shows it" to="/docs/reference/terminology#console-activity-and-secrets">write-only secret</Terminology>, so the **Connection** page and ordinary read routes don't show it after you save it. A freshly confirmed export can include it in plain text.
3. Lets you check the saved connection at any time without running an <Terminology title="One fixed pfSense task you can call, like ping or wake" to="/docs/reference/terminology#core-concepts">action</Terminology>.

## Set Up the Connection

A new installation has no connection, so **Overview** shows **Connect to pfSense**, and every <Terminology title="One fixed pfSense task you can call, like ping or wake" to="/docs/reference/terminology#core-concepts">action</Terminology> answers `503` until you save one.

1. Select **Set up the connection**, or open **Connection**.
2. Fill in the fields described below, then select **Test and save**.

If you try to open another page or sign out after changing a field, the console asks before discarding it. Refreshing or closing the browser tab uses the browser's unsaved-changes warning too.

## View the Connection

- **Overview** shows the firewall's address, the SSH username, and the sign-in method under **pfSense**, with the credential hidden.
- **Connection** shows the same values under **Saved connection**, with a form to change them below.

## Test the Saved Connection

Select **Test connection** on **Overview** or **Connection**.

**Last test** shows whether the sign-in worked, and the sidebar's connection status changes to match. The <Terminology title="A trial SSH sign-in to pfSense that runs nothing" to="/docs/reference/terminology#console-activity-and-secrets">connection test</Terminology> only signs in, so it doesn't ping or wake anything, and its result appears in the <Terminology title="Who did what and when, for the newest 250 events" to="/docs/reference/terminology#console-activity-and-secrets">activity log</Terminology>.

To hear about a connection that stops working without testing it yourself, add a <Terminology title="Where an alert goes: ntfy, Telegram, email, webhook" to="/docs/reference/terminology#notifications">notification destination</Terminology> that chose **pfSense can't be reached**. pfSense Actions then runs a <Terminology title="A sign-in every 5 minutes to notice pfSense going down" to="/docs/reference/terminology#notifications">scheduled check</Terminology> every 5 minutes, as described in [Notifications](/docs/console/notifications/#the-scheduled-check).

## Change Settings

1. Open **Connection** and find **Change connection**.
2. Edit **pfSense address**, **SSH port**, and **SSH username** as needed.
3. Choose **Private key** or **Password** under **Sign in with**.
4. Enter a new credential, or leave the field empty to keep the saved one.
5. Select **Test and save**.

<Frame caption="Changing the connection">
  <ThemedImage sources={{ light: pfsenseConnectionTwoLight, dark: pfsenseConnectionTwoDark }} alt="Change connection form with the pfSense address, SSH port, and SSH username filled in, Private key selected under Sign in with, an empty private key field that keeps the saved key, and Test and save" width={992} height={591} style={{ maxWidth: '100%', height: 'auto' }} />
</Frame>

| Field               | What it accepts                                                               |
|---------------------|-------------------------------------------------------------------------------|
| **pfSense address** | An IPv4 or IPv6 address, not a hostname.                                      |
| **SSH port**        | A number from 1 to 65535.                                                     |
| **SSH username**    | Up to 128 characters.                                                         |
| **Private key**     | The whole private key, including its BEGIN and END lines, with no passphrase. |
| **Password**        | The account's SSH password.                                                   |

pfSense Actions saves the settings only if the <Terminology title="A trial SSH sign-in to pfSense that runs nothing" to="/docs/reference/terminology#console-activity-and-secrets">connection test</Terminology> signs in with them. If it can't, nothing changes, and the console reports the failure next to **Test and save**.

Switching between **Private key** and **Password** needs a new credential, because the saved one belongs to the other method.

## Enter the Credential Again

If pfSense Actions started without its <Terminology title="Locks saved secrets; lose it and they're wiped" to="/docs/reference/terminology#storage-and-backups">encryption key</Terminology>, it keeps the connection's address, port, username, and sign-in method, but removes the password or private key.

- **Sign-in** under **Saved connection** shows `Password, not saved` or `Private key, not saved`, and the sidebar shows `Not connected` with `Enter the password again` or `Enter the private key again`.
- Every <Terminology title="One fixed pfSense task you can call, like ping or wake" to="/docs/reference/terminology#core-concepts">action</Terminology> answers `503`, and **Test connection** reports `Enter the password or private key again, then save the connection.`
- The <Terminology title="A sign-in every 5 minutes to notice pfSense going down" to="/docs/reference/terminology#notifications">scheduled check</Terminology> for notifications stops until the credential is back, so **pfSense can't be reached** isn't sent in the meantime.

Enter the password or private key under **Change connection** and select **Test and save**. [Backup and Recovery](/docs/operations/backup-and-recovery/#lost-encryption-key) covers what else a lost key removes.

## Environment File Values

:::warning
The `PFSENSE_*` environment variables are deprecated <Terminology title="Old PFSENSE_* settings that only seed an empty database" to="/docs/reference/terminology#console-sign-in">bootstrap values</Terminology>. When they're set and no connection is saved yet, or its password or private key was removed, pfSense Actions imports them as the connection on its next start, without testing them, and logs a warning at every start while they're set.

Change the connection on this page instead, and remove the variables.
:::

## Export and Import

The **Backup** section near the end of **Connection** makes a portable <Terminology title="A JSON backup that can hold secrets in plain text" to="/docs/reference/terminology#storage-and-backups">export file</Terminology> or brings one into this installation. Use **Export…** or **Import…** beside **Export and import**; neither action uses the connection form's save flow.

  <ThemedImage sources={{ light: pfsenseConnectionFourLight, dark: pfsenseConnectionFourDark }} alt="Backup panel with Export and import, Save this setup to a file, or bring one in, and the Export and Import buttons" width={960} height={133} style={{ maxWidth: '100%', height: 'auto' }} />
</Frame>

### Export

1. Select **Export…**.
2. Keep every section selected, or clear anything that should stay out of the file.
3. Select **Continue**.
4. Complete <Terminology title="A fresh sign-in check before export or import" to="/docs/reference/terminology#console-activity-and-secrets">**Confirm it’s you**</Terminology>, then select **Confirm**.

The downloaded file is named `pfsense-actions-export-YYYY-MM-DD.json`. Its selected sections are:

- **Connection** — The pfSense SSH address, port, username, sign-in method, and password or private key. When a lost encryption key removed the password or private key, save it again before exporting, because a file with an empty one can't be imported.
- **Notifications** — Every <Terminology title="Where an alert goes: ntfy, Telegram, email, webhook" to="/docs/reference/terminology#notifications">destination</Terminology>, its events and settings, and its <Terminology title="A destination's token or password, saved but never shown" to="/docs/reference/terminology#notifications">secret fields</Terminology>.
- **Access tokens** — <Terminology title="The pfa_ key a script sends to call the API" to="/docs/reference/terminology#access-tokens">Token</Terminology> names, scopes, expiry, timestamps, and stored hashes. Raw token values are never stored and cannot be put in the file.

:::warning
The pfSense password or private key and notification secrets are plain text in the file. Keep it somewhere safe; importing it does not need the source <Terminology title="Locks saved secrets; lose it and they're wiped" to="/docs/reference/terminology#storage-and-backups">encryption key</Terminology>.
:::

### Confirm It's You

<Terminology title="A fresh sign-in check before export or import" to="/docs/reference/terminology#console-activity-and-secrets">Confirm it’s you</Terminology> asks for the current password and, when the authenticator app is on, its current 6-digit **Authenticator code**. Select **Use a passkey instead** to use a <Terminology title="Sign in with your device, no password or code needed" to="/docs/reference/terminology#console-sign-in">passkey</Terminology>.

The confirmation lasts five minutes, works once, is limited to export or import, and belongs only to the current <Terminology title="Keeps you signed in to the console for 24 hours" to="/docs/reference/terminology#console-sign-in">browser session</Terminology>. Using another browser, waiting longer, or switching operations requires another confirmation.

### Import

1. Select **Import…**.
2. In **Source**, choose **A pfSense Actions export**. The JSON file must be smaller than 10 MB.
3. In **Settings**, compare **In the file** with **Here**.
4. In **Review**, check the exact additions, replacements, and skips, then select **Import**.
5. Complete <Terminology title="A fresh sign-in check before export or import" to="/docs/reference/terminology#console-activity-and-secrets">**Confirm it’s you**</Terminology>, then select **Confirm**.

<Frame caption="Review lists every change before anything is applied">
  <ThemedImage sources={{ light: pfsenseConnectionFiveLight, dark: pfsenseConnectionFiveDark }} alt="Import dialog on Review with Ready to import and checked lines to replace the pfSense connection, replace 4 notification targets with the same name, and skip 2 access tokens that are already here, above notes that everything is applied at once and that the administrator account, sign-in security, sessions and activity history stay here" width={1064} height={590} style={{ maxWidth: '100%', height: 'auto' }} />
</Frame>

The import applies every selected section in one database transaction. If any section fails, none of its changes are kept.

- **Connection** — Added when this installation has no saved connection, or replaced when it does. A file with no saved connection leaves the current one unchanged.
- **Notifications** — A <Terminology title="Where an alert goes: ntfy, Telegram, email, webhook" to="/docs/reference/terminology#notifications">destination</Terminology> with the same name, without regard to letter case, is replaced. A new name is added.
- **Access tokens** — A token with a new ID, name, and stored hash is added. A token whose ID, case-insensitive name, or hash already exists is skipped, so an import never creates a duplicate.
- **Sections not in the file** — Existing values in those sections stay as they are.

The imported connection and notification secrets are encrypted with this installation's <Terminology title="Locks saved secrets; lose it and they're wiped" to="/docs/reference/terminology#storage-and-backups">encryption key</Terminology>. Imported token hashes keep their existing raw token values working, but the file cannot reveal or reissue those values.

### What Stays Here

An export never contains these, and an import doesn't replace them. **Review** notes that they stay here.

- **Administrator account and password** — They protect this pfSense Actions.
- **Authenticator, passkeys and recovery codes** — They stay bound to this account and hostname.
- **Browser sessions and setup claims** — They remain local to this pfSense Actions.
- **Activity history** — It describes work performed here. The import adds one `backup-imported` event to it.

Use [Backup and Recovery](/docs/operations/backup-and-recovery/#choose-an-export-or-data-volume-backup) to choose between this portable file and a complete data-volume backup.

## Debug Logging

**Diagnostics** at the end of **Connection** holds the **Debug logging** switch. Turn it on while you track down a problem, then turn it off again, because it makes the log much longer. It takes effect right away, stays on after a restart, and each change appears in the <Terminology title="Who did what and when, for the newest 250 events" to="/docs/reference/terminology#console-activity-and-secrets">activity log</Terminology>.

<Frame caption="Debug logging at the end of Connection">
  <ThemedImage sources={{ light: pfsenseConnectionSixLight, dark: pfsenseConnectionSixDark }} alt="Diagnostics panel with Debug logging, Adds DEBUG lines to the container log while you track down a problem, and its switch turned off" width={960} height={132} style={{ maxWidth: '100%', height: 'auto' }} />
</Frame>

While it's on, pfSense Actions adds `DEBUG` lines to the [container log](/docs/operations/container-operations/#read-the-logs):

- **SSH to pfSense** — Each sign-in, and each command such as `ping -c 5 192.0.2.25`, with its exit code and how long it took.
- **The scheduled check** — Whether pfSense answered the <Terminology title="A sign-in every 5 minutes to notice pfSense going down" to="/docs/reference/terminology#notifications">scheduled check</Terminology>, and how long it took.
- **Notifications** — Each alert and **Send test**, by destination name, with whether it was delivered and how long it took.
- **Slow and canceled requests** — Console and API requests that took a second or more, and requests the browser canceled before the answer arrived.

The lines `debug logging is on` and `debug logging is off` mark each change. `LOG_LEVEL="warn"` or `LOG_LEVEL="error"` hides the `DEBUG` lines too.
