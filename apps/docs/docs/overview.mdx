Give scripts and home-automation tools a small set of pfSense <Terminology title="One fixed pfSense task you can call, like ping or wake" to="/docs/reference/terminology#core-concepts">actions</Terminology> without sharing your firewall login or a remote shell.

## What Is pfSense Actions?

pfSense Actions is a small self-hosted <Terminology title="pfSense Actions itself, the go-between for your clients" to="/docs/reference/terminology#core-concepts">controller</Terminology> that sits between your automation and one pfSense firewall. It signs in to the firewall over SSH, runs one fixed operation per request, and reports the result.

## Why Use pfSense Actions?

1. Keeps the pfSense login in one place, so each script holds only its own <Terminology title="The pfa_ key a script sends to call the API" to="/docs/reference/terminology#access-tokens">personal access token</Terminology>.
2. Limits each token to named <Terminology title="What a token may do; each action needs exactly one" to="/docs/reference/terminology#access-tokens">scopes</Terminology>, so a <Terminology title="Turns on a sleeping device with a magic packet" to="/docs/reference/terminology#api-actions">Wake-on-LAN</Terminology> shortcut can't run other <Terminology title="One fixed pfSense task you can call, like ping or wake" to="/docs/reference/terminology#core-concepts">actions</Terminology>.
3. Answers with a <Terminology title="You get the outcome, never raw firewall output" to="/docs/reference/terminology#core-concepts">data-minimizing response</Terminology>, so scripts learn the outcome without seeing firewall output.
4. Includes an <Terminology title="The /admin web page for tokens and settings" to="/docs/reference/terminology#core-concepts">operations console</Terminology>, so you can create and revoke tokens without editing files.
5. Sends alerts to ntfy, Telegram, email, and other services when pfSense stops answering or sign-in is locked, so you hear about a problem before a script runs into it.

## Supported Actions

| Request                    | What it does                                                                                                                                                                 | Scope               |
|----------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------|
| `GET /api/v1/connectivity` | Checks that pfSense Actions can sign in to the firewall.                                                                                                                     | `pfsense:read`      |
| `GET /api/v1/system`       | Returns the firewall's operating system, release, and architecture.                                                                                                          | `pfsense:read`      |
| `POST /api/v1/ping`        | Asks the firewall to ping one IP address.                                                                                                                                    | `reachability:read` |
| `POST /api/v1/wol`         | Sends a <Terminology title="Turns on a sleeping device with a magic packet" to="/docs/reference/terminology#api-actions">Wake-on-LAN</Terminology> packet from the firewall. | `wol:execute`       |

The same actions also answer at `GET /`, `GET /system`, `POST /ping`, and `POST /wol`, so scripts written for 1.x keep working.

## What It Doesn't Do

- It doesn't run arbitrary commands or open a remote shell for callers.
- It doesn't change, import, or export pfSense configuration.
- It doesn't replace the pfSense web interface, and the <Terminology title="The /admin web page for tokens and settings" to="/docs/reference/terminology#core-concepts">operations console</Terminology> can't change firewall settings.
- It manages one <Terminology title="The one pfSense box this install controls" to="/docs/reference/terminology#core-concepts">target firewall</Terminology> per deployment.

## How It Works

1. Your script sends a request with its <Terminology title="The pfa_ key a script sends to call the API" to="/docs/reference/terminology#access-tokens">personal access token</Terminology>.
2. pfSense Actions checks the token and its <Terminology title="What a token may do; each action needs exactly one" to="/docs/reference/terminology#access-tokens">scope</Terminology> before contacting the firewall.
3. It signs in to the firewall over SSH, runs the commands for that <Terminology title="One fixed pfSense task you can call, like ping or wake" to="/docs/reference/terminology#core-concepts">action</Terminology>, and signs out.
4. Your script receives a status code and a small JSON result, or three system fields for `GET /api/v1/system`.

## Requirements at a Glance

- **pfSense firewall** — SSH turned on and an account that pfSense Actions can sign in with.
- **A host to run it** — Docker with Compose on an amd64 or arm64 machine, or Node.js 22, 24, or 26 to run from source.
- **HTTPS** — A <Terminology title="The HTTPS front door, like Caddy, ahead of the controller" to="/docs/reference/terminology#deployment-and-container">reverse proxy</Terminology> or another encrypted path for any traffic that leaves the host.
