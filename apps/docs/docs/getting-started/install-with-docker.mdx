Run pfSense Actions with the repository's Docker Compose file, which builds the image on your host and publishes the console and API on port 22603.

## Why Use This Deployment?

1. Publishes port 22603 on every IPv4 and IPv6 address of the Docker host, so devices on your network can open the console. The [HTTPS reverse proxy](/docs/getting-started/https-reverse-proxy/) guide covers a <Terminology title="Listen on 127.0.0.1 only, so just the host can reach it" to="/docs/reference/terminology#deployment-and-container">loopback binding</Terminology> that limits it to the Docker host.
2. Needs no passwords or keys in files, because you create the <Terminology title="The one login for the console; tokens can't sign in" to="/docs/reference/terminology#console-sign-in">administrator account</Terminology> in the browser with a one-time <Terminology title="The one-time code from the log that creates your login" to="/docs/reference/terminology#console-sign-in">setup code</Terminology> from the container log.
3. Keeps the <Terminology title="The one SQLite file that holds everything" to="/docs/reference/terminology#storage-and-backups">controller database</Terminology> and its generated <Terminology title="Locks saved secrets; lose it and they're wiped" to="/docs/reference/terminology#storage-and-backups">encryption key</Terminology> on a named <Terminology title="The Docker volume that keeps your data across updates" to="/docs/reference/terminology#storage-and-backups">data volume</Terminology> that survives rebuilds.
4. Runs the service as a non-root user under <Terminology title="Starts the controller in the container and restarts it" to="/docs/reference/terminology#deployment-and-container">s6-overlay</Terminology>, with a built-in <Terminology title="Docker's 30-second check that the service is listening" to="/docs/reference/terminology#deployment-and-container">health check</Terminology>.

## Requirements

- **Docker with Compose** — Docker Engine with the Compose plugin and BuildKit, on an amd64 or arm64 host.
- **Repository checkout** — `compose.yml` builds the image from the root of the [pfSense Actions repository](https://github.com/mrjackyliang/pfsense-actions).
- **Prepared pfSense** — SSH turned on and an account ready, as described in [Prepare pfSense](/docs/getting-started/prepare-pfsense/).
- **HTTPS plan** — A <Terminology title="The HTTPS front door, like Caddy, ahead of the controller" to="/docs/reference/terminology#deployment-and-container">reverse proxy</Terminology> for any client that isn't on the Docker host, covered in [HTTPS Reverse Proxy](/docs/getting-started/https-reverse-proxy/).

## Change the Host Settings

`compose.yml` works without an environment file. To change the user the service runs as or its time zone, copy the root sample file and edit it.

```bash
cp .env.sample .env
```

```bash title=".env"
PGID="1000"
PUID="1000"
TZ="UTC"
```

Every variable and its default is listed in the [Configuration Reference](/docs/reference/configuration/).

The service always listens on port 22603 inside the container. To publish a different host port, change the left side of the `ports` mapping in `compose.yml`, such as `"8080:22603"`, or use `-p 8080:22603` with `docker run`. With host networking, the port is always 22603.

## Build and Start

Build the image and start the service from the repository root.

```bash
docker compose up --build --detach
```

`npm run deploy:container` runs the same command. On the first start, pfSense Actions creates the <Terminology title="The one SQLite file that holds everything" to="/docs/reference/terminology#storage-and-backups">controller database</Terminology> and an <Terminology title="Locks saved secrets; lose it and they're wiped" to="/docs/reference/terminology#storage-and-backups">encryption key</Terminology>, which it saves as `keys/installation.key` in the <Terminology title="The Docker volume that keeps your data across updates" to="/docs/reference/terminology#storage-and-backups">data volume</Terminology>.

## Find the Setup Code

While no <Terminology title="The one login for the console; tokens can't sign in" to="/docs/reference/terminology#console-sign-in">administrator account</Terminology> exists, pfSense Actions prints a <Terminology title="The one-time code from the log that creates your login" to="/docs/reference/terminology#console-sign-in">setup code</Terminology> in its log.

```bash
docker compose logs app
```

```text
WARN No administrator account exists yet. Open the console at /admin/ to create it.
WARN Setup code: ABCDE-FGHJK-LMNPQ (valid until 2026-01-01T12:30:00.000Z; restart the container for a new one)
```

- The code works once and lasts 30 minutes, and `docker compose restart app` prints a new one.
- Anyone who can read the container log can use the code, so it's worth creating the account right after the first start.

## Create the Administrator Account

1. Open `http://<docker-host>:22603/admin/`, where `<docker-host>` is the name or address of the machine that runs Docker. Use your host port if you changed the mapping, or your HTTPS address once the proxy is in place.
2. Enter the **One-time code** from the log. Letter case, spaces, and dashes don't matter.
3. Choose a **Username** and a **Password** of 12 to 1,024 characters, repeat the password in **Confirm password**, and select **Create account**. The bar under the field rates it from **Weak** to **Strong**, and any password in that range is accepted.

The console signs you in right away, and the setup screen doesn't appear again.

## Connect pfSense

1. On **Overview**, select **Set up the connection**.
2. Enter the firewall's IP address, the SSH port, and the SSH username.
3. Choose **Private key** or **Password** under **Sign in with**, and paste the credential.
4. Select **Test and save**.

pfSense Actions saves the connection only after it signs in with it, as described in [pfSense Connection](/docs/console/pfsense-connection/).

## Create a Token

Create a <Terminology title="The pfa_ key a script sends to call the API" to="/docs/reference/terminology#access-tokens">personal access token</Terminology> with the `pfsense:read` <Terminology title="What a token may do; each action needs exactly one" to="/docs/reference/terminology#access-tokens">scope</Terminology> as described in [Access Tokens](/docs/console/access-tokens/), and copy it while the console shows it.

## Verify a Request

Send one <Terminology title="Can pfSense Actions sign in to pfSense? Yes or no" to="/docs/reference/terminology#api-actions">connectivity check</Terminology> from the Docker host, keeping the token out of the process list.

```bash
read -r -s PFSENSE_ACTIONS_TOKEN

printf 'header = "Authorization: Bearer %s"\n' "$PFSENSE_ACTIONS_TOKEN" \
  | curl --config - --silent --show-error \
      --write-out '\nHTTP %{http_code}\n' \
      http://127.0.0.1:22603/api/v1/connectivity

unset PFSENSE_ACTIONS_TOKEN
```

`HTTP 200` with `{"connected":true}` means pfSense Actions signed in to the firewall and ran `uname -mrs`. `HTTP 502` means the SSH sign-in or the command failed, which [Troubleshooting](/docs/operations/troubleshooting/#requests-get-502) covers.

## Get Alerts

To hear when pfSense stops answering or sign-in is locked, add a <Terminology title="Where an alert goes: ntfy, Telegram, email, webhook" to="/docs/reference/terminology#notifications">notification destination</Terminology> on the console's **Notifications** page, as described in [Notifications](/docs/console/notifications/).

## What the Data Volume Holds

The <Terminology title="The Docker volume that keeps your data across updates" to="/docs/reference/terminology#storage-and-backups">data volume</Terminology> `pfsense_actions_data` is mounted at `/data` and holds two things.

- **`pfsense-actions.sqlite3`** — The <Terminology title="The one SQLite file that holds everything" to="/docs/reference/terminology#storage-and-backups">controller database</Terminology>, with its `-wal` and `-shm` files. It holds the <Terminology title="The one login for the console; tokens can't sign in" to="/docs/reference/terminology#console-sign-in">administrator account</Terminology> with an Argon2id password hash, <Terminology title="Keeps you signed in to the console for 24 hours" to="/docs/reference/terminology#console-sign-in">browser sessions</Terminology>, each <Terminology title="All that's stored of a token; lose it and you replace it" to="/docs/reference/terminology#access-tokens">token hash</Terminology> and its <Terminology title="What a token may do; each action needs exactly one" to="/docs/reference/terminology#access-tokens">scopes</Terminology>, the encrypted pfSense connection, the encrypted <Terminology title="The six-digit code from your authenticator app" to="/docs/reference/terminology#console-sign-in">TOTP</Terminology> secret, <Terminology title="A one-use backup code for when your phone is gone" to="/docs/reference/terminology#console-sign-in">recovery code</Terminology> hashes, <Terminology title="Sign in with your device, no password or code needed" to="/docs/reference/terminology#console-sign-in">passkey</Terminology> public keys, <Terminology title="Where an alert goes: ntfy, Telegram, email, webhook" to="/docs/reference/terminology#notifications">notification destinations</Terminology> with their encrypted <Terminology title="A destination's token or password, saved but never shown" to="/docs/reference/terminology#notifications">secret fields</Terminology>, and the <Terminology title="Who did what and when, for the newest 250 events" to="/docs/reference/terminology#console-activity-and-secrets">activity log</Terminology>.
- **`keys/installation.key`** — The generated <Terminology title="Locks saved secrets; lose it and they're wiped" to="/docs/reference/terminology#storage-and-backups">encryption key</Terminology>, readable only by the service's user. If it goes missing, pfSense Actions makes a new one and removes the saved pfSense password or private key, the authenticator app, and every <Terminology title="Where an alert goes: ntfy, Telegram, email, webhook" to="/docs/reference/terminology#notifications">destination</Terminology>'s <Terminology title="A destination's token or password, saved but never shown" to="/docs/reference/terminology#notifications">secret fields</Terminology>, as described in [Backup and Recovery](/docs/operations/backup-and-recovery/#lost-encryption-key).

Raw tokens, raw recovery codes, and plaintext passwords or private keys aren't stored in the volume. The pfSense credential and notification secrets leave it in plain text only inside an export file you download.

:::warning
The volume holds both the database and the key that decrypts it, so anyone with a copy of the volume can read the stored pfSense credential and notification secrets. Keep volume backups as safe as the firewall credential itself, as described in [Backup and Recovery](/docs/operations/backup-and-recovery/).
:::

:::info
The image is built on `node:24.22.0-trixie-slim`, pinned by digest, with <Terminology title="Starts the controller in the container and restarts it" to="/docs/reference/terminology#deployment-and-container">s6-overlay</Terminology> 3.2.3.2 downloaded from GitHub and checked against its SHA-256 checksums. Builds for any platform other than amd64 or arm64 stop with an error.
:::
