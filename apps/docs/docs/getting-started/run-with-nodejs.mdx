Run pfSense Actions directly with Node.js for development, or on a host you manage yourself, without Docker.

## Requirements

- **Node.js 22, 24, or 26** — The API workspace supports Node.js 22, 24, and 26, and the repository pins npm 11.18.0.
- **Repository checkout** — Commands run from the root of the [pfSense Actions repository](https://github.com/mrjackyliang/pfsense-actions).
- **Prepared pfSense** — SSH turned on and an account ready, as described in [Prepare pfSense](/docs/getting-started/prepare-pfsense/).

## Install Dependencies

```bash
npm install
```

## Configure the Environment File

Copy the sample file. Every value in it is optional, so you can leave it as it is.

```bash
cp apps/api/.env.sample apps/api/.env
```

- `DATA_DIRECTORY` defaults to `.data` in the folder the process starts in, which is `apps/api` for the npm scripts.
- The service always listens on port 22603.
- On the first start, pfSense Actions creates `database/pfsense-actions.sqlite3` and generates an <Terminology title="Locks saved secrets; lose it and they're wiped" to="/docs/reference/terminology#storage-and-backups">encryption key</Terminology> at `keys/installation.key` in the data directory. If that file goes missing, pfSense Actions makes a new key and removes the saved pfSense password or private key, the authenticator app, and every <Terminology title="Where an alert goes: ntfy, Telegram, email, webhook" to="/docs/reference/terminology#notifications">notification destination</Terminology>'s <Terminology title="A destination's token or password, saved but never shown" to="/docs/reference/terminology#notifications">secret fields</Terminology>, as described in [Backup and Recovery](/docs/operations/backup-and-recovery/#lost-encryption-key).
- The `PFSENSE_*` values are deprecated <Terminology title="Old PFSENSE_* settings that only seed an empty database" to="/docs/reference/terminology#console-sign-in">bootstrap values</Terminology>. Leave them empty to set everything up in the <Terminology title="The /admin web page for tokens and settings" to="/docs/reference/terminology#core-concepts">operations console</Terminology>.

:::warning
A source run listens on every network interface, as the Compose setup does. Because the listener serves plain HTTP, it's recommended to block the port with a host firewall or reach it only through a <Terminology title="The HTTPS front door, like Caddy, ahead of the controller" to="/docs/reference/terminology#deployment-and-container">reverse proxy</Terminology>.
:::

## Run in Development

```bash
npm run dev --workspace pfsense-actions-app-api
```

This starts two processes, and both reload when a source file changes.

- **API** — Runs the source with `tsx watch` on port 22603, loads `apps/api/.env`, and sets `NODE_ENV` to `development`.
- **Console** — Serves the console with Vite at `http://localhost:5174/admin/` and passes its API calls to port 22603.

## Build and Run in Production

```bash
npm run build --workspace pfsense-actions-app-api
npm run prod --workspace pfsense-actions-app-api
```

`build` compiles the API into `apps/api/build` and the console into `apps/api/build/admin`. `prod` runs `node build/index.js` with `NODE_ENV` set to `production`, and it doesn't read `apps/api/.env`.

Set the variables in the process environment instead, for example through your service manager.

## Create the Administrator Account

On the first start, the output shows a <Terminology title="The one-time code from the log that creates your login" to="/docs/reference/terminology#console-sign-in">setup code</Terminology> in a line such as `2026-01-01T12:00:00.000Z WARN pfsense-actions: Setup code: ABCDE-FGHJK-LMNPQ`. Open the console, which is `http://localhost:22603/admin/` after a build or `http://localhost:5174/admin/` in development, and create the account as described in [Install with Docker](/docs/getting-started/install-with-docker/#create-the-administrator-account).
